# 会话历史加载与缓存

打开会话时，支持分页的 Codex 历史只读取最近 12 轮，较早历史按同样大小分片。每轮的条目按 20 条读取，以保留大工具输出的 JSONL 传输边界。旧版 legacy 历史没有分页能力，沿用全量读取；导出始终读取完整已保存历史。

向上滚动进入距顶部约 1.5 个视口（至少 600px）的区域时开始预加载。每个会话最多一个历史读取请求；较早内容加载后保留，因此向下滚动或重复经过同一区域不产生重复请求。未到边界不继续扫描整段历史。插入分片以稳定轮次 ID 恢复首个可见轮次的偏移，流式更新保留当前阅读位置。到达末页停止；失败保留已加载内容并提供重试。切换会话取消历史读取，迟到结果也会检查所属会话。

## 本机缓存

IndexedDB 中每条记录对应一个历史分片。再次打开或刷新页面时只读取最近一片；滚动需要的较早分片再单独查缓存，同时与服务端核对。服务端按稳定轮次 ID 替换整轮内容，所以回复修改、轮次状态与新增消息都会得到校正。缓存不恢复 WebSocket 游标，也不参与任务执行、自动恢复或审批。显示缓存时会提示正在同步或同步失败，活动中的缓存状态降为“未知”，操作入口等待真实服务端数据。

缓存范围由经过认证的接口确认，包含当前服务端进程、Codex 实例、用户身份、项目 ID、根目录及可用性。用户身份只在服务端参与哈希，不保存 JWT 或明文用户标识。重启服务或 Codex、切换用户、改变项目上下文都会生成新命名空间。认证失败、会话删除或访问被拒绝时，不再显示该会话缓存并清理相应记录。完全离线的新页面无法重新确认身份，因此不会读取此前身份下的缓存；已确认身份的页面遇到临时网络故障时可以继续阅读缓存；历史请求失败后，可通过“继续读取本机历史”逐片读取更早的缓存，不再发起网络请求。重新同步会串行核对本次已打开的缓存分片。

消息数据总量上限 8 MiB，单片最多 512 KiB，有效期 7 天。写入时按最早写入时间回收超额、过期或版本不兼容的记录；读取会拒绝过期或校验失败的记录。缓存摘要用于检测损坏。超过单片上限的内容仍正常从服务端读取。浏览器拒绝存储、清理数据、配额耗尽或缓存损坏均按未命中处理，不影响服务端分页。浏览器清理本网站数据可删除全部缓存。

## 验证

- `node --import tsx scripts/benchmark-history.ts`：独立进程读取相同的 125 轮模拟历史，记录优化前全量路径与分页路径的耗时、原生 RPC 次数及结果字节数。
- `tests/integration/thread-history-pages.test.ts`：验证首次只读一页、继续分页无重复遗漏、恢复不读全量、游标归属及 legacy 回退。
- `tests/e2e/session-history.spec.ts`：运行生产构建页面，覆盖预加载、锚点保持、快速切换、错误重试、刷新缓存命中、跨设备式内容校正、网络失败、权限撤销、损坏及存储不可用；截图与耗时记录保存在 Playwright 产物中。

缓存命中后仍需读取最近一片以核对最新状态；较早历史仅在阅读到该处时核对，不会在重开时无条件下载全部历史。

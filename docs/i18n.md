# Interface localization

The interface supports `zh-Hans`, `en`, `ja`, and `ko`. Resources are bundled with the application and use i18next with react-i18next. Dates, numbers and units use the browser's `Intl` implementation and local time zone.

## Language selection

A supported manual choice in `localStorage` (`covro.locale`) takes precedence over the ordered `navigator.languages` preferences. Unsupported preferences are skipped; if none match, use English. An explicit Chinese script takes precedence over the region. `zh`, `zh-CN`, `zh-SG` and `zh-Hans` match Simplified Chinese; `zh-Hant`, `zh-TW`, `zh-HK` and `zh-MO` do not. Traditional Chinese is a future language, not a Simplified Chinese alias.

Storage failures never prevent opening or changing the interface. A choice still applies to the current page if browser policy prevents saving. Language changes update `html[lang]` and are shared with other open tabs through storage events.

## Message boundaries

Only application-owned UI text belongs in the resources. User prompts, model responses, tool output, command text, upstream rationales, project names, paths and IDs remain verbatim. Approval decisions are submitted using their original IDs, independently of their translated labels. Changing the interface language must not submit a task or change model/runtime settings.

Missing or empty translated messages fall back to English. The UI translation wrapper uses a localized generic failure if an unknown key reaches it. Resources must have matching keys and interpolation variables; tests enforce this. Keep complete sentences in resources, pass dynamic values through interpolation, and use plural messages for quantities. Do not translate protocol values or markers used to parse upstream text.

## Extending resources

Keep resources under `src/web/i18n/locales/<language>/`, grouped by feature. English is the reference catalog. Add the same message key and interpolation parameters in all four languages. Use the same terms consistently: session, model, reasoning effort, approval, automatic review, archive and fork. A session fork copies saved history; it does not move or interrupt the original execution.

Use the browser's existing time zone. Localization changes presentation, never timestamp units, UTC offsets, elapsed-time calculation or the meaning of execution state. Eager resources avoid loading placeholders or remounting the workspace during a language change.

## UI integration

The sidebar selector uses each language's own name. The React subscription updates labels in place, retaining session IDs, drafts, open previews, approval decisions and execution state. Conversation and sidebar scroll anchors account for language changes. Shared server permission enforcement stays independent of translated presentation labels.

Application notices retain a message key and interpolation values until rendering. API failures use stable error codes for the translated explanation, with the untouched original diagnostic available in an expandable technical section. Project clone jobs provide stable progress stages and error codes; changing language preserves the clone identity, destination, draft and percent. Legacy server prose remains available as technical details. Backup records use their stable phase and trigger for translated presentation; raw progress and failure diagnostics stay in technical details. Backup notices retain their message identity, and catalog timestamps and sizes follow the selected interface language without changing IDs, paths, commands or the active operation. Automatic review notifications provide structured presentation fields so program names, arguments and paths are not parsed out of translated prose.

Chinese completion labels retain the established absolute date and UTC-offset layout. Other locales use native date ordering. All preserve the browser time zone, historical offset, original timestamp units and full seconds. Numbers and duration units use locale-aware formatting; quantity messages include singular and plural forms.

Validation includes locale negotiation and resource integrity tests, plus real Chromium flows for all four languages, persistent manual choices, storage failures, cross-tab changes, approval IDs, drafts, read-only previews and 390px layouts. Backend fixture content intentionally remains in its original language.
